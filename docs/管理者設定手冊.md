# 管理者設定手冊(只需要做一次)

這份是給負責建置的人(目前是張弘佶)。照順序做,大約 1 小時。做完之後,
其他人只需要看《使用手冊》。

整套系統由四個免費服務組成,**沒有任何一台需要一直開著的實驗室主機**:

| 服務 | 負責什麼 | 費用 |
|---|---|---|
| Google 試算表 | 取代 HeidiSQL/MySQL,存所有資料 | 免費 |
| GitHub(repo + Actions) | 放程式碼;Actions 是 GitHub 的雲端電腦,負責下載年報、跑 AI | 免費 |
| Gemini API | AI 判讀重要契約 | 免費額度(每天有上限) |
| Streamlit Community Cloud | 大家使用的網頁 | 免費 |

> 重要:以下所有帳號請用**實驗室共用的 Google 帳號**申請,不要用個人帳號,
> 畢業交接時才不會整套跟著某個人消失。

---

## 步驟 1:建立 Google 試算表

1. 用實驗室 Google 帳號開一份空白試算表,命名「重要契約研發合作資料庫」。
2. 網址長這樣:`https://docs.google.com/spreadsheets/d/【這一串】/edit`,把【這一串】記下來,這就是 **SHEET_ID**。

## 步驟 2:建立 Google 服務帳號(讓程式能寫試算表)

1. 到 <https://console.cloud.google.com/>,左上角「選取專案」→「新增專案」,名稱隨意(例如 smart-spider)。
2. 搜尋列輸入「Google Sheets API」→ 點進去 →「啟用」。
3. 左側選單「API 和服務」→「憑證」→「建立憑證」→「服務帳戶」,名稱隨意,其餘直接按完成。
4. 點進剛建好的服務帳戶 →「金鑰」分頁 →「新增金鑰」→「JSON」,會下載一個 `.json` 檔。**這個檔案等同密碼,不要上傳到 GitHub、不要傳到群組。**
5. 用記事本打開 JSON,找到 `"client_email"` 後面那個 email(結尾是 `iam.gserviceaccount.com`)。
6. 回到步驟 1 的試算表 → 右上角「共用」→ 貼上這個 email → 權限選「編輯者」→ 傳送。

## 步驟 3:申請 Gemini API 金鑰

到 <https://aistudio.google.com/apikey> → Create API key,記下金鑰(**GEMINI_API_KEY**)。
免費額度每天能處理的份數有限,且 Google 會調整;目前預設每次處理 20 份,用完會自動隔天繼續。
如果之後想一次回補很多年份,可以在 AI Studio 開啟付費提高額度,費率以 Google 當時公告為準。

## 步驟 4:把舊資料搬進試算表(在任何一台電腦跑一次)

在已經裝好環境的電腦上(就是你之前裝好 `.venv` 那個資料夾):

```bat
copy .env.example .env
```

用記事本打開 `.env`,填:

```
SHEET_ID=步驟1那一串
GOOGLE_SERVICE_ACCOUNT_FILE=D:\keys\smart-spider.json   (步驟2下載的檔案放哪就填哪)
```

然後:

```bat
pip install -r requirements.txt
python scripts/setup_sheet.py --history "D:\路徑\半導體上市 2025.xlsx"
```

跑完打開試算表,應該會看到五個分頁,「契約資料」裡有 4,437 筆舊資料、「公司清單」裡有公司代碼。
重複跑也不會重複搬。

## 步驟 5:在 GitHub 設定雲端排程

1. 打開 <https://github.com/tiger-lab-png/smart-spider> → Settings → Secrets and variables → Actions → **New repository secret**,新增三個:

   | Name | 內容 |
   |---|---|
   | `GEMINI_API_KEY` | 步驟 3 的金鑰 |
   | `SHEET_ID` | 步驟 1 那一串 |
   | `GOOGLE_SERVICE_ACCOUNT_JSON` | 用記事本打開步驟 2 的 JSON,**整份全選複製貼上** |

2. 上方「Actions」分頁 → 如果有提示,按「I understand my workflows, go ahead and enable them」。
3. 左側點「自動更新重要契約資料」→ 右邊「Run workflow」→ max_items 填 `2` → Run。等幾分鐘,點進去看紀錄。
4. 打開試算表的「處理紀錄」分頁,應該多了兩筆。**這一步最重要,用來確認雲端真的抓得到公開資訊觀測站**(見文末「已知風險」)。

## 步驟 6:建立給大家用的網頁

1. 到 <https://share.streamlit.io/> → 用 GitHub 帳號登入 → Create app → 選「Deploy a public app from GitHub」。
2. Repository:`tiger-lab-png/smart-spider`、Branch:`main`、Main file path:`app.py`。
3. 「Advanced settings」:Python 版本選 3.11;**Secrets** 欄位照 `.streamlit/secrets.toml.example` 的格式貼上所有金鑰,並自己設一組 `APP_PASSWORD`(給實驗室成員的密碼)。
4. 按 Deploy,幾分鐘後會得到一個 `https://xxxx.streamlit.app` 網址,這就是要給大家的網址。

## 步驟 7:讓網頁上的「一鍵更新」按鈕能動

1. GitHub 右上角頭像 → Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token。
2. Repository access:只選 `smart-spider`;Permissions → Repository permissions → **Actions:Read and write**(其他都不用)。
3. 到期日選最長,產生後複製(`github_pat_` 開頭)。
4. 回 Streamlit 的 App settings → Secrets,加上 `GITHUB_APP_TOKEN = "剛剛那串"`,存檔。
5. 打開網站首頁,應該看得到「一鍵更新」按鈕和最近執行紀錄。

## 已知風險與對策

1. **雲端能不能抓到公開資訊觀測站,還沒實測。** GitHub 的雲端電腦在國外,公開資訊觀測站是否會擋國外連線、下載程式是否完全符合網站現在的結構,要用步驟 5 第 3 點實際跑才知道。如果「處理紀錄」全部是「抓不到年報」:
   - 先在台灣網路的電腦上跑 `python -m src.scraper.download_annual_reports --debug --stock 2303 --year 2024`,確認本機抓不抓得到;
   - 本機抓得到、雲端抓不到 → 代表擋國外連線,改成在實驗室任何一台電腦上跑 `python -m src.cloud.run_update`(只有跑的那十幾分鐘需要開著,結果一樣寫進試算表,網頁照常使用);
   - 本機也抓不到 → 下載程式要依網站現況調整;在那之前,大家可以先用網頁的「手動上傳年報」。
2. **GitHub 的每日排程,在 repo 60 天沒有任何更新時會被自動暫停**(GitHub 的規定,會寄信通知)。網頁上的「一鍵更新」按鈕不受影響;要恢復每日自動,到 Actions → 該 workflow → Enable workflow。
3. **Streamlit 免費網頁一陣子沒人用會休眠**,打開時按喚醒等一分鐘即可,資料都在試算表,不會遺失。
4. **Gemini 免費額度每天有上限**,且 Google 會調整,一次大量回補會分好幾天完成。
5. 「是否有合作方向」1/2/3/4 代碼是從舊資料反推的,請老師確認正式定義後改 `config/schema.py` 的 `DIRECTION_CODE_MEANING`。
